# 任务与工位状态机（classic；develop 移植契约）

## 权威记录与不变量

任务卡 `tasks` 是任务的权威记录；`rooms` 的认领代次、所属聊天频道和桥接标记是工位的权威记录。频道消息是可操作的投影，不是状态推断来源。交付、验收和释放工位是三个不同动作。**绝不以超时自动验收代替人的判断**；超时只能提醒、暂停或收回没有任务的空认领。不会把每个工具步骤转发频道，只发布待处理的提问、权限、失败、暂停、交回、验收和结束。

| 状态 | 有权动作 | 工位 | 频道投影 |
| --- | --- | --- | --- |
| assigned / accepted / rework | 接活人进展、提问或 `[report]` | 占用 | 派活、进展摘要、到点暂停 |
| asked | 接活人提问；用户明确答复后继续 | 有效提问占用 | 问题及就地回复入口 |
| paused (`paused_at`，保留原状态) | 派活人恢复/改派，或接活人继续交回 | 不占用 | 暂停原因、恢复入口 |
| declined / escalated | 派活人改派、取消或返工 | 不占用 | 原因和待决动作 |
| returned | 派活人或不同于作者的独立验收者 `done` / `rework` | 不占用 | 结果和验收/返工入口 |
| done | 无；终态 | 不占用 | 验收人及结论 |

只有接活人能表态、交回；接活人不能把自己的进行中任务标成 `done`。派活人、经授权的独立验收者或用户可以验收及返工，返工必须给原因。聊天里的一般发言不能隐式验收，也不是答复；`[report]` 只到 `returned`。桥接卡的 `failed/cancelled/interrupted` 是失败交回而不是成功结果，须由派活人选择返工或结束。负责人确已移除时由系统标记无法继续并交派活人处理，不自动成功。

## 转移与副作用

1. 派活创建 `assigned` 和任务卡；认领工位记录 `claim_task` 基线和 `claim_seq`，创建任务前的空认领在宽限期后可收回。
2. `【接】` 或进展只续看门；有效 `[ask]` / `【问】` 持久化独立待答复记录并投影到聊天频道。只有对对应提问卡的回复（或明确 token）才确认答复并重启检查时钟。无效提问在原工位提示纠正，也在频道显示待处理的格式错误；纠正失败不能假装已交回。
3. 权限请求在工位及聊天频道同时显示；决定必须指向仍在运行的原始请求。重启后旧卡设过期，频道明确提示重试；旧卡绝不批准新执行轮次。
4. 会话中断、断网和重启保留任务记录并向频道暴露失败待处理项；人工恢复继续原任务或明确取消，不能靠失败卡自动完成。检查器从持久任务和认领恢复，重复运行不得重复交回或释放。
5. `[report]` 绑定结果消息，把 `returned` 和验收入口送到聊天频道，释放非桥接工位。`【退】/【升】` 同理告知派活人作决定；工位释放不能丢任务。
6. 返工或暂停恢复前核对当前认领代次和频道。原工位空闲则按原任务重新认领并接续会话；异频道已占用则在原频道给出新工位重新交接动作，不能把原频道结果误投到新频道，也不能静默拒绝并丢卡。
7. 非桥接认领只有该次交接任务交回或完成、没有其余进行中任务后才自动释放；刚认领尚未派活的空工位按宽限期回收。桥接认领只由桥接持有者携本次 `claim_seq` 显式释放，旧代次不得释放新认领。

## 十种场景的验收

1. `[report]` 后为 `returned`，频道就地验收，作者本人不能验收。
2. 仅 `【接】` 或进展不交回；无进展超十分钟暂停并通知频道。
3. 有效 `[ask]`/`【问】` 持久等待明确回复；普通频道消息不答复。
4. 无效 `[ask]` 的纠正请求在工位和频道均可见；补发仍走原任务。
5. 待权限在频道处理，重启令旧请求过期并提供重新发起路径。
6. 会话失败、断网、重启在频道有可处理的恢复/结束决定；不会自动验收。
7. `【退】/【升】` 和交回即使释放工位仍在频道保持待处理卡。
8. 返工/暂停恢复遇异频道认领提供重新交接入口；原任务和结果不丢失。
9. `claim_task=0` 的空认领在宽限期后回收，新任务刚开始不误收。
10. 桥接认领由桥接结束操作按代次释放，DSH 交回不越权释放。

## 兼容和验证边界

classic 先落实 DSH 任务、问答、工位及 API；共享问答规则同时核对 Go bundle。移植 develop 时以文件/函数为单位用 `git apply --check` 检查：能直接应用的作为通用补丁，其余明确所需适配和验证，不以文档声称代码已部署。构建、bundle 哈希及测试输出分别记录；任何失败单列。
