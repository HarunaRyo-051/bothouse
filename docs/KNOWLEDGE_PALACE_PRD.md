# 知识宫殿 / 鱼塘需求 PRD

## 1. 背景与问题

产品经理同时负责多个业务平台，政策和需求资料分散在各自的本地文件夹。
做新需求时，逐份找规则费时；只靠关键词容易漏掉限制条件。
现有便签检索不能直接读取 Office/PDF，也没有经确认的文件引用关系。
需要在不搬动原件的前提下，建立可核对出处、不会跨平台串用的知识视图。

## 2. 目标用户与场景

- **整理材料：** 产品经理把 A 平台政策 PDF、需求 Word 和网页摘录放在已有的 A 平台文件夹里，要求 AI 生成可追溯便签，自己确认分类与文件引用，再从星图核对关系。
- **分析新需求：** 同一频道里先做 A 平台事项、后做 B 平台事项；产品经理分别选定平台，查看逐份查阅的材料、适用条款及缺口，避免拿 A 的规则回答 B 的问题。

## 3. 需求清单

每条可单独答复「要 / 不要 / 改」。P0 为第一版必需，P1 为第二版重点，P2 为后续候选。

| 编号 | 需求 | 为什么 | 优先级 | 怎么算做完 |
| --- | --- | --- | --- | --- |
| R1 | 登记已有平台文件夹，并在各平台目录内生成可重建的 `wiki/` 便签；原件不搬、不改、不删。 | 避免维护第二套资料目录。 | P0 | A、B 两个平台可分别登记；删除便签后可重建，原件内容和位置不变。 |
| R2 | 读取本地 Word、PPT、Excel、PDF 及保存正文的网址摘录，生成带原句、定位、来源版本和读取状态的便签。 | 仅有链接或无出处摘要不能核对。 | P0 | 每条要点可定位到原文件页、幻灯片、工作表单元格或段落；读不清时明确标出，不编造内容。 |
| R3 | AI 建议文件属于哪些鱼塘，由用户逐份确认，允许一份文件归多个塘。 | 分类应由人把关，原件不必按塘搬动。 | P0 | 未确认建议不成为正式归属；详情能看到已确认的一个或多个塘。 |
| R4 | AI 只在找到可核对原句时提议有方向的「A 引用了 B」，用户逐条确认或否决。 | 相似主题不能证明引用。 | P0 | 提议展示两端文件、各自版本、原句和位置；未确认不作为既定引用。 |
| R5 | 保存确认与否决记录；同版本、同证据的否决不重复提议。 | 减少重复审核。 | P0 | 再次整理相同材料不弹出同一提议；记录可查方向、证据、版本和决定。 |
| R6 | 提供独立「星图」页：一塘一星团、一文件一星；仅把当前有效且已确认的引用画成从引用方指向被引用方的实线。 | 让用户看到真实的文件关系，不把猜测画成事实。 | P0 | 可缩放、漫游、按塘定位、点星开详情；跨塘引用可找到两端，未确认关系无实线。 |
| R7 | 文件详情显示摘要、塘、版本、读取状态和双向引用，并可打开证据原句及原件位置。 | 看图后必须能核查。 | P0 | 从任一星可进入详情；点引用可核对原句和页、表或段；原件不可访问时明确提示。 |
| R8 | 每件新事项显式选择所属平台，同一事项沿用；未选时不引用平台专属规则。 | 同一频道会交替处理不同平台。 | P0 | 连续办理 A、B 事项互不串库；未选平台可讨论事实，但无平台规则结论；改选提示查阅范围变化。 |
| R9 | 新需求先逐份查相关塘，遇明确引用或已登记公共规范再跨塘追读；搜索和连线只作补充。 | 只看搜索命中容易漏掉限制。 | P0 | 展示逐份查阅记录及追读原因；不因别的平台资料词语相似就自动纳入。 |
| R10 | 规则结论逐条给出原句、出处、触发事实、适用条件、例外、版本和缺失事实。 | 引用关系本身不证明条款适用于本次需求。 | P0 | 缺事实写「待确认」；不能从便签摘要直接宣称规则有效。 |
| R11 | 提供「这次查了什么」面板，列出查过、没查、缺件、读不清、版本不明及其影响。 | 局部查询不能冒充全平台无规定。 | P0 | 文件夹失效、云盘占位、受保护文件和便签缺失有不同提示；无命中不显示「没有要求」。 |
| R12 | 原件内容变更后保留旧确认历史，将对应引用标为「待复核」并撤下当前实线，复核后恢复或撤销。 | 旧证据不能自动代表新版本。 | P1 | 修改原件可见旧原句与版本；复核前没有有效实线，复核决定留痕。 |
| R13 | 主题相关与引用分开提议和审核，不以主题相似生成引用实线。 | 用户需要两种关系，但证据含义不同。 | P1 | 待审列表和详情可辨两类关系；主题相关的图上呈现方式待单独确认。 |
| R14 | 支持按原句搜索并回到文件位置，同时第二遍检查禁止、例外、时限等限制。 | 补足逐份查阅时可能遗漏的硬条件。 | P1 | 可由搜索结果打开出处；资质、时限、审批、口径等标「找到依据 / 查过但没找到 / 信息不足」。 |
| R15 | 仅在用户将材料标为公共规范或批准本事项的具体跨平台追查后读取跨平台资料，并逐条核对适用范围。 | 公共可检索不等于自动适用，更不能串入其他平台规则。 | P0 | 每次跨平台读取显示目标、理由与范围；未授权不能读取其他平台专属资料。 |

## 4. 用户流程

1. 在已有平台文件夹中保留原始材料；网页保存关键正文，同时记录网址、原标题和保存时间。
2. 登记各平台文件夹；新事项开始时选所属平台，归属不明先补充事实并确认平台。
3. 点击「整理资料」；系统读原件、记录版本与异常，在对应平台的 `wiki/` 中生成可重建便签。
4. 审核 AI 建议的鱼塘归属，再逐条核对带原句的引用提议并确认或否决。
5. 从独立星图按塘定位并打开文件详情，查看经确认的引用及其证据。
6. 做需求时先逐份查相关塘；遇确认的引用或明确公共规范再追读，按许可处理跨平台资料。
7. 查看逐条规则的适用理由与「这次查了什么」；缺件、读不清、条件不足时补资料或保留待确认项。
8. 原件更新后重建便签，复核受影响的旧关系，再用新版本作结论。
