# 知识宫殿 / 鱼塘系统设计稿

## 一句话说明

给同时负责多个平台的产品经理用：原始资料留在已有文件夹里，AI 帮忙做有出处的知识便签；用户确认分类和引用后，可以按鱼塘找规则、沿星图看文件之间的联系。

## 用户怎么用

1. 在已有的平台文件夹里整理资料。Word、PPT、Excel、PDF 放在「原始材料」；网页先保存关键正文到本地，保留网址、保存时间和原网页标题。
2. 登记这个平台的文件夹。开始一件新需求时，选它属于哪个平台；同一个聊天频道里，下一件事可以选另一个平台。归属不清时先聊需求，暂不引用任何平台规则，并请用户确定归属。
3. 点「整理资料」。AI 逐份读取原件，生成带出处的便签，并建议文件属于哪个鱼塘。用户确认鱼塘归属，原件不移动。
4. AI 提议「这份文件引用了那份文件」，展示双方文件、引用原句和位置。用户逐条确认或否决；确认后才出现实线。
5. 做新需求时，先逐份查看相关鱼塘的材料；遇到明确引用或公共规范，再追到相应鱼塘。搜索和沿已有连线找是补充，不能代替逐份查看。回答列出条款原句、需求中的触发事实、适用条件、例外和版本；缺事实就写「待确认」。
6. 从星图缩放、漫游、点开文件看详情，或从回答打开「这次查了什么」。没找到依据只表示在已查范围内没找到，不等于没有要求。

## 目录长什么样

沿用用户已有的文件夹，不另造一套平行项目目录。下面以实际已有的「工作」目录为例；鱼塘是经确认的分类，不要求用户再搬一次原件。

```text
工作/
├── A平台/                       用户已有的平台文件夹
│   ├── 原始材料/                 用户管理；原件不由工具改写或删除
│   │   ├── 需求说明.docx
│   │   ├── 业务规则.pdf
│   │   └── 网页摘录.md           本地正文，附原网址和保存时间
│   └── wiki/                     工具生成的便签，可从原件重建
│       ├── README.md             目录标识，不作为知识正文
│       ├── 需求说明.md
│       └── 业务规则.md
├── B平台/                       同样保留原件，并有自己的 wiki/
└── 公共规范/                     仅存用户明确标为跨平台的材料
    ├── 原始材料/
    └── wiki/
        ├── README.md
        └── 通用条款.md
```

每个平台的检索范围指向整个平台文件夹，知识正文放在其 `wiki/` 中。现在的检索方式不会收录文件夹最外层的 Markdown，也不会把 `README.md` 当正文；缺少 `wiki/README.md` 会漏掉整个子目录。必须另外限制只读 `wiki/` 里的便签，免得平台文件夹里别的 Markdown 被误当规则。`wiki/` 是生成物，可删除后重建；确认过的分类、引用、否决和原件版本记录须另存为工具管理的记录，不能随便删掉。具体存储形式留给实现设计，不要求用户手管第二套项目文件夹。

## 页面

**星图页。** 一塘一星团，一份文件一颗星。用户能缩放、漫游、按塘定位、点星打开详情。箭头实线只表示「A 引用了 B」且经用户确认，方向从 A 指向 B；没确认的不画成事实。塘内通常不到十份，但不假设总文件数也只有十份。跨塘确认的引用仍能找到两端。主题相关也要支持查找：它与引用不同，不能冒充引用实线；具体是否画另一种线须单独确认，不以「相关」推断「引用」。

**文件详情。** 显示原件名称、所在塘、内容摘要、版本和读取状态；列出「引用了谁」「被谁引用」，每项都能点到确认所依据的原句和原文件页码、表格位置或段落。多塘归属需要确认，不会因 AI 的建议自动生效。打不开原件时保留历史记录，但明确提示无法核对。

**「这次查了什么」面板。** 每次给出规则依据时，列出事项所属平台、逐份读过的鱼塘和文件、追查的引用或公共规范、各文件版本与时间，以及没查、缺件、读不清、版本不明的项目。结论逐条附原句、出处、适用理由、限制和待确认事实；检查资质、时限、审批、口径等硬条件时标「找到依据 / 查过但没找到 / 信息不足」。局部查完不显示「全平台无规定」。

## 索引怎么生成

用户选择平台后，AI 使用相应的文档读取能力读取 Word、PPT、Excel、PDF 和本地网页摘录；扫描件识别不清时标为「读不清」，不猜字。网页保存正文而非仅存链接；遇到网页后续变化，以本地保存版本为准并提示回看原站。

每份原件生成一张或多张知识便签，记讲什么、可检索的要点和逐条出处。每条至少记录原文件路径、页 / 幻灯片 / 工作表及单元格 / 段落（依格式选可定位的位置）、引用原句、内容版本；另记生成时间和读取异常。版本用于发现同一路径下原件内容改变，不只是看文件名。便签是帮助检索的草稿，不等于已经确认的规则；回答仍须回到原件核对条款和适用条件。

原件更新或便签被删后可重新读取并生成。重建只替换生成便签，不抹去用户确认、否决或历史版本；出处失效、版本变化要显眼地提示。没有便签或原件无法读取时，不能报告「已查全」。

## 关系怎么确认

提议卡写明「需求说明引用了业务规则」的方向、两份文件各自的版本、引用原句及页 / 表 / 段、为什么认为它指向该文件；能直接打开原件核对。没有可核对的原句，不生成引用提议。用户在卡片上点「确认」或「否决」；只有确认的引用成为星图实线。否决记录保留文件对、引用方向、原句、对应版本和理由（可不填）；相同版本和证据不重复提议，版本改变时先提示旧否决而不是静默重提。

主题相关与引用分开标记：用户最初两种关系都要，但「同主题」的证据不能证明引用。先把主题相关放在待审列表和详情中，单独确认其含义及显示方式后再画图。确认按一条关系操作，不要求用户对每段相似文字反复点确认。

**待用户拍板：素材更新后，旧的确认还算不算？**

- 甲：照旧保留实线，只加「原件已更新」提示。操作少，但旧线可能误导。
- 乙：内容版本变化后暂时隐藏实线，重新确认才能恢复。最谨慎，但一次改动可能让图上的线全消失。
- 丙（建议）：保留旧线的历史记录，但图上不再把它画成当前有效的实线；标「待复核」，展示原确认的原句与旧版本。用户对新版本复核后恢复实线或撤销。既不丢决定，也不把旧决定冒充新事实。此项由用户拍板后才能确定最终交互。

## 多平台不串

平台归属绑定在**这一件事**，不是整个频道，也不是某个 AI 成员。新事项先明确选平台，同一事项后续沿用；改归属时提示此前引用范围会改变。归属不明时，不查任何平台专属资料，也不引用平台规则；可继续讨论需求事实并询问归属。

跨平台只走明确例外：用户先把资料指定为公共规范，或在当前事项里批准一次具体的跨平台追查，并显示追查目标、理由和范围。读到引用或公共规范才扩展查阅；别的平台资料不会因为与问题用词相似就自动混入。公共资料「查得到」不等于自动适用于每个平台，仍要核对适用范围与例外。

## 出错时怎么办

| 情况 | 用户看到的提示与下一步 |
| --- | --- |
| 平台文件夹改名或挪动 | 「找不到 A 平台文件夹；本次未查 A 平台资料。」请重新指定已有文件夹；不显示「没有相关规定」。 |
| 云盘尚未同步或只有占位文件 | 「文件尚未下载，未读到正文。」列出缺失文件，等待同步后重试；缓存便签标为旧版，不算已核对。 |
| 文件损坏、受密码保护或权限不足 | 「这份文件读不了：原因及文件名。」标出受影响的结论，让用户修复权限或换可读文件后重试。 |
| 原文件改名、移动或内容已变 | 「找不到原件」或「原件版本已变，出处待复核」；给出旧位置与重新关联入口，不静默套用旧引用。 |
| 便签目录缺失、空白或读取失败 | 「知识便签未生成 / 无法读取；本次检索不完整。」检查目录标识并允许重建，不把零命中当作无规则。 |

## 分期与验收

**第一版：跑通一件事。** 登记已有平台目录；保存网页摘录；读取常见 Office/PDF 与本地摘录，生成带版本出处的便签；用户确认塘归属和引用提议，否决过的相同证据不再提；画可点开的星图实线；新需求按事项选平台、逐份看相关塘并展示查阅范围与失败状态。跨塘遇明确引用或已登记的公共规范再追读。验收：用户用 A、B 两个平台各放几份材料，A 的新需求只能得到 A 的依据；不选平台时没有平台规则；点 A 的一条确认线能核对原句；移走 A 文件夹后显示「找不到」而不是「无规定」；回答能列出读过和没读到的文件。

**第二版：处理变化和遗漏。** 原件变更提醒与旧确认复核（按用户拍板方案）、跨版本否决提示、主题相关的独立审核与展示、搜原句、限制条件第二遍检查和硬条件清单；跨塘材料增多时保留查阅记录。验收：用户改一处原件后能辨认旧线和新版本；否决同一证据后不会反复弹出；找一句原文能回到文件位置；遗漏资料不会被写成「没有要求」。

**以后：扩大规模与协作。** 经用户另行确认后再考虑多人共享、批量整理、从已确认关系反查受影响需求以及更复杂的图上筛选。验收：用户按真实规模的材料和协作方式复测查阅边界、权限和出处，不以小样本演示替代验证。

## 要改的现有东西

现成的文件便签检索与每轮推送可以借用，但还不能直接当这套系统用：

1. `bridge/contrib/gate/wiki_search.py`：现在只收符合目录规则的 Markdown，不直接读取 Office/PDF；平台文件夹里的其它合规 Markdown 也可能被收。需增加受控的便签收录范围，以及原件读取和生成便签的独立流程。
2. `bridge/contrib/gate/ctxsvc.py`：现在按公共主目录加「按成员身份」的目录查，不按事项选平台；目录不存在时返回空，索引还有缓存。需支持按事项明确选择平台、限制公共资料、报告目录失效与读取状态，并保证切换或重建后不继续推旧内容。
3. `dsh/collab/gate-context.mjs` 和对应聊天 / 工作区入口：当前传的是成员身份，没有事项平台与查阅边界。需保存事项归属，传递选定范围，向用户展示每次查了什么；桥接的其他入口也要遵守相同隔离规则。
4. 新增材料读取与版本记录、分类及关系审核、星图与文件详情的产品能力；这些不是现有便签检索自带的功能。星图只展示确认过的引用实线。以上是改动位置与职责，不是实现代码。

## 明确不做的

- 不另建一棵平台资料目录，不自动搬动、改写或删除原件。
- 不把 AI 自动分类、提取的摘要或相似度直接当成确认的规则或引用线。
- 不让未选平台的事项猜平台，也不把整个频道固定到某个平台。
- 第一版不做多人权限、自动改政策原文、凭一条搜索结果宣称「全平台没有规定」。
- 主题相关不冒充引用；是否及如何画成另一种线，须在后续单独确认。
